**FIX — `AUTOMERGE_PAT` expirado derrubava o safety net de auto-merge de todos os PRs; rotação concluída com o token do keyring do `gh` (2026-09-19):** toda execução de `.github/workflows/agent-pr-ready-automerge.yml` ficava vermelha com `GitHub GraphQL → 401 … {"message":"Bad credentials"}` no `enablePullRequestAutoMerge` — ~30 falhas consecutivas desde 2026-09-18T21:39:59Z (primeira: run 35397905870, branch `fix/c193-missed-rename`; último sucesso 20:43:58Z, run 35393045267), nenhum PR armava auto-merge (merges à mão com o token do keyring) e o `auto-unblock.yml`, que entrega o mesmo secret ao agente destacado, também estava quebrado. Causa-raiz: o secret `AUTOMERGE_PAT` era um PAT fine-grained criado no lote do OPS71 em 2026-08-20T01:31:17Z (~30d default), nunca rotacionado, expirou ~2026-09-18T20:57Z (mesma janela do `GITHUB_TOKEN` local do lote); a rotação ficara só registrada como pendência no post-mortem do dia anterior, sem dono/lembrete/detector, e nenhuma API expõe valor/validade do secret — o CLI é fail-closed por desenho (`scripts/github-pr-automerge.mjs:60-65,81`; `automergeArmingToken` em `scripts/lib/github-pr-flow.mjs`; `.github/workflows/agent-pr-ready-automerge.yml:58-65`), pois um merge como `github-actions[bot]` não cria runs de `closed`/`push` (OPS71-FLIP, PR #746), então nenhuma mudança de repo conserta credencial morta. Fix: com autorização humana explícita (`docs/AGENT-OPS.md:27` — secrets de repo são "só humano"), `gh secret set AUTOMERGE_PAT --body "$(env -u GITHUB_TOKEN gh auth token)"` em 2026-09-19T05:55:11Z (`gh secret list` confirma o `updatedAt`), passando o valor ao token OAuth longevo do keyring (`gho_`, sem os ~30d, revogação manual, escopos `gist`/`read:org`/`repo`/`workflow`) — o mesmo token alimenta o `GITHUB_TOKEN` local, então `gh auth status` vermelho vira o indicador antecedente dos dois.
