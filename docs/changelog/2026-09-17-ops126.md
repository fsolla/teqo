**OPS126 — auto-unblock volta a despachar de verdade no homeserver: fetch honra o proxy e o opencode é resolvido fora do PATH (2026-09-17):** duas causas independentes mantinham o agente de desbloqueio (OPS106) sem entregar nada. **(1) `fetch failed` no launcher:** o homeserver só alcança o GitHub pelo proxy CONNECT local (`github-tunnel` + `http-proxy-socks`, `~/actions-runner/.env` com `HTTPS_PROXY/HTTP_PROXY=127.0.0.1:1081`); o `fetch` global do Node ignora `HTTP(S)_PROXY` a menos que `NODE_USE_ENV_PROXY` seja definido **antes** do processo subir (Node ≥24), então a leitura dos jobs do run caía em conexão direta e falhava de forma intermitente (run `35171293357`: 4/4 `fetch failed` e nenhum token criado). `scripts/auto-unblock.sh` passa a exportar `NODE_USE_ENV_PROXY=1` quando há proxy configurado — o agente destacado herda. **(2) exit 127 do agente:** o serviço do runner não carrega o profile interativo, então `~/.opencode/bin` não está no PATH e o `timeout ... opencode` morria com _No such file or directory_ (log `unblock-35101121310.log`), deixando o token `blocked` sem PR. Novo helper puro `resolveOpenCodeBinary` (`OPENCODE_BIN` → argv0 com path → `$HOME/.opencode/bin/<argv0>` → PATH) é usado pelo wrapper e pelo `--check` (que agora acusa o binário ausente em vez de passar), e o launcher falha fechado **antes** de provisionar o worktree quando o binário não existe.
