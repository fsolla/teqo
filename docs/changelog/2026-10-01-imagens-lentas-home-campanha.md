**Fix — home da campanha lenta: masters AVIF 4K servindo recortes de 177–747px (2026-10-01):** o relato "Images are loading slowly in jorgesolla1313.com.br" reproduziu em produção: `/_next/image` com TTFB ~1,6s nas miniaturas 256w e um request de `RUI - 2-2.avif&w=256` pendurado >120s. Causa-raiz: os 5 masters do hero (`CampaignHero`) iam de 3840×5757 a 3840×5760 (14–22MP, 1,03–3,60MB) para exibir 177–702px — decode de ~0,7–1,1s de sharp por derivado (benchmark local; soma 4324ms) —, e a combinação `images.minimumCacheTTL` default 60s + cache volátil do container + `cf-cache-status: DYNAMIC` regenerava quase toda miniatura no homeserver; os masters nasceram do default do `pnpm images:resize` ("2x desktop", 3840px) aplicado a recortes pequenos. O fix regera os 5 masters com o próprio `pnpm images:resize` (`RUI`/`WAGNER`/`Jeronimo` 768px, `Lula` 1024px, `JOA00162` 1536px; 350,9KB vs 8,7MB — otimizador 11× mais rápido, soma 381ms), sobe `images.minimumCacheTTL` para 14400 (`next.config.mjs:10`), tira o percent-encoding dos srcs (`/RUI - 2-2.avif`, `/WAGNER - 2-9 final.avif`) e corrige os `sizes` do hero para os caps reais do CSS (211px/284px/747px); o gerador ganha aviso quando a saída ≥2000px.
