# OPS99 — Generate importMap during build with dummy S3\_\* envs

**Date:** 2026-08-27
**Issue:** #928
**Type:** ops, bug-fix

## Summary

Generate the Payload importMap at build time (Dockerfile) and dev time (predev hook) with dummy S3\_\* envs, eliminating the class of bugs where the admin goes blank because the S3ClientUploadHandler entry is missing (OPS69/OPS72/OPS73).

## Changes

### Dockerfile

- Added `pnpm generate:importmap` step with dummy S3\_\* envs BEFORE `next build`
- This ensures the production image always has the correct importMap with S3ClientUploadHandler

### Scripts

- **Added:** `scripts/predev-importmap.mjs` — predev hook that generates importMap if missing or stale
- **Deleted:** `scripts/check-importmap-s3.mjs` — guard script no longer needed (importMap is now generated at build time)
- **Deleted:** `tests/unit/importMapS3UploadHandler.unit.spec.ts` — unit pin no longer needed

### CI/CD

- Removed `check-importmap-s3.mjs` step from `ci-pr.yml` and `deploy.yml`

### Configuration

- Added `src/app/(payload)/admin/importMap.js` to `.gitignore` (build artifact, not committed)
- Added `scripts/check-importmap-s3.mjs` to `.gitignore` (deleted file)

### Documentation

- Updated `AGENTS.md` with new importMap contract
